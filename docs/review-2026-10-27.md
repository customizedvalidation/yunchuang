## 5. 留作后续建议（未本轮修，需目标环境 / 决策）

下列项要么需要 GitHub runner / K8s 集群验证，要么需要产品决策，本地改了也无法验证，故不在本轮 commit 内。

### CI / GitHub Actions（`.github/workflows/ci-cd.yml`）
- `checkov soft_fail: true`（ci-cd.yml:83）：IaC 发现不阻断 PR。建议生产分支对 HIGH/CRITICAL 阻断。
- Trivy 只跑 `scan-type: fs`，未对构建推送的镜像做 `scan-type: image`；建议加镜像扫描 job。
- 缺 `cargo audit` / `cargo deny`；建议加 Rust 依赖 CVE 扫描。
- SSH 部署用 `-o StrictHostKeyChecking=no`（ci-cd.yml:328,374,435）：建议预植 host key 或 ssh-agent。
- SSH 部署 `git pull && cargo build --release && systemctl restart ... || true` 与 GHCR 镜像路径脱节，`|| true` 吞失败；建议收敛为单一路径。
- 缺 kubeconform/kubeval schema 校验、actions/dependency-review、SBOM 生成。
- `npm audit --audit-level=high` 失败被 `|| echo ::warning` 降级（ci-cd.yml:165-167）。

### K8s
- `k8s/13-kustomization.yaml:45,47` `images.newTag: main` 是浮动分支 tag；建议生产 base 用不可变 SHA tag，`main` 降到 dev overlay。
- `k8s/05-deployment.yaml:73` `automountServiceAccountToken: false` 与 ConfigMap `K8S_ENABLED: "true"` + Role 授予 jobs create 矛盾：要么真调 K8s API（挂 token），要么关 K8S_ENABLED、删 Role。需产品决策。
- `k8s/17-postgresql.yaml` / `18-redis.yaml` 用 `postgres:16-alpine` / `redis:7-alpine` 浮动 minor tag + `imagePullPolicy: Always`；建议钉 digest 或具体 patch tag。
- `k8s/18-redis.yaml` `--requirepass "$(REDIS_PASSWORD)"` 与探针 `-a "$(REDIS_PASSWORD)"` 把口令暴露在容器 `ps`；建议改 redis.conf + 600 权限文件。
- `k8s/09-networkpolicy.yaml:115-124` egress 放行 K8s API 用 podSelector 选 `kube-apiserver`，托管控制面通常不命中；建议改 ipBlock 放行 API Server ClusterIP。
- 两份 Dockerfile 基础镜像未钉 digest（`rust:1.96-alpine` / `alpine:3.20` / `node:22-alpine` / `nginx:alpine`）。

### 后端
- `src/services/inference.rs`、`src/services/partition_permission.rs` 无单测/集成测试；建议补 list/get 路径与跨租户负向用例（需要测试 DB harness）。
- `src/auth/middleware.rs:120-133` JWT 撤销名单在 Redis 故障时 fail-open；建议加 `REVOCATION_FAIL_CLOSED=true` 开关。
- `src/middleware/security_headers.rs:90` 开发 CSP 含 `'unsafe-inline'`；建议 staging 也强制生产 CSP。
- `src/metrics/business.rs` / `src/metrics/http.rs` 共 17 处启动期 `.expect("register ...")`；建议改 `once_cell::sync::Lazy`（启动期可接受，非紧急）。

### 前端
- `src/stores/auth.ts` localStorage 存 user 对象（含 role）是既定设计（httpOnly Cookie 才是凭证），建议在 README/安全说明显式声明"role 仅用于 UI 过滤，服务端才是 authz 边界"。
- docs/ 与 backend docs/ 下大量 2026-09 旧复盘报告与当前基线漂移，建议集中归档或加"历史记录"横幅。
